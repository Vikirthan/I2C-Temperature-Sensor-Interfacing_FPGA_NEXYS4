# I2C Temperature Sensor Interface on FPGA (Nexys A7)

A Verilog implementation of an I2C master controller that reads temperature data from an onboard sensor and displays it on the 7-segment display and LEDs of the Nexys A7 FPGA board.

---

## What it does

The design continuously polls a temperature sensor over I2C at 10 kHz, pulls the 16-bit response (MSB + LSB), extracts the 8-bit integer Celsius value, and pushes it to two output peripherals simultaneously — the 4-digit 7-segment display and 8 onboard LEDs (binary representation).

No external components needed. The Nexys A7 already has a TMP sensor connected to the PMOD header pins, and the constraints file maps everything accordingly.

---

## Project Structure

```
├── top.v                   # Top-level module, wires everything together
├── i2c_master.v            # I2C master FSM — handles start, address, data, ACK/NACK
├── clkgen_200kHz.v         # Clock divider: 100 MHz → 200 kHz (used to derive 10 kHz SCL)
├── seg7.v                  # 7-segment display controller with multiplexing
├── i2c_master_TB.v         # Testbench for the I2C master
├── const_temp_sensor.xdc   # Vivado constraints (pin mappings for Nexys A7)
└── Temperature_Sensor_interfacing.xpr   # Vivado project file
```

## How the I2C master works

The FSM has 28 states that walk through a full I2C read transaction:

1. **POWER_UP** — waits ~10ms on startup before doing anything
2. **START** — pulls SDA low while SCL is high (I2C start condition)
3. **SEND_ADDR[6:0] + RW** — sends the 7-bit sensor address (`0x48`) with R/W bit set to read (`1`), so the full byte transmitted is `0x97`
4. **REC_ACK** — releases SDA and waits for sensor to pull it low
5. **REC_MSB[7:0]** — clocks in the 8 MSBs of the temperature register
6. **SEND_ACK** — master pulls SDA low to acknowledge it received the MSB byte
7. **REC_LSB[7:0]** — clocks in the 8 LSBs
8. **NACK** — master sends NACK to tell the sensor it's done, then loops back to START

The actual temperature in °C comes from bits `[14:7]` of the 16-bit response (i.e., `{tMSB[6:0], tLSB[7]}`), which gives the integer part of the reading.

SCL runs at 10 kHz, generated by dividing the 200 kHz clock by 20 (toggle every 10 counts) inside `i2c_master.v`. The 200 kHz clock itself comes from dividing the 100 MHz board clock by 500 in `clkgen_200kHz.v`.

## Pin Assignments (Nexys A7)

| Signal     | Pin  | Notes                        |
|------------|------|------------------------------|
| CLK100MHZ  | E3   | Onboard 100 MHz oscillator   |
| reset      | C12  | Center button (BTNC)         |
| TMP_SCL    | F16  | I2C clock to sensor          |
| TMP_SDA    | G16  | I2C data (bidirectional)     |
| led[7:0]   | T8–U6| Binary temperature in °C     |
| seg[6:0]   | L3–L6| 7-segment cathodes           |
| an[3:0]    | N6–N5| Active digit anodes          |
| NAN[3:0]   | N2–M1| Upper anodes, kept OFF       |

## Running the project

1. Open `Temperature_Sensor_interfacing.xpr` in Vivado (tested on 2020.x+)
2. Run Synthesis → Implementation → Generate Bitstream
3. Program the Nexys A7 via USB-JTAG
4. The display should start showing room temperature within a second of programming

To simulate first, add `i2c_master_TB.v` as a simulation source and run behavioral simulation. The testbench exercises the master FSM and lets you verify state transitions before touching hardware.

---

## Notes

- The SDA line uses a tri-state assignment (`assign SDA = SDA_dir ? o_bit : 1'bz`) to handle the bidirectional nature of I2C. `SDA_dir` is driven high whenever the master owns the bus and low when it's listening.
- The temperature register on this sensor defaults to the ambient reading with no configuration needed — the design does a simple read-only transaction on every loop.
- Timing is tight to the 200 kHz clock via hardcoded counter thresholds in the FSM. If you change the clock frequency, those thresholds need to be recalculated.
